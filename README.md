# 1C Universal Dev

Codex skill для разработки и анализа решений на платформе 1С:Предприятие 8.

## Содержимое

- SKILL.md — маршрутизация задач, общие правила и порядок выбора штатного решения для исправления данных.
- references/ — инструкции по коду, ревью, БСП, запросам, формам, архитектуре, расширениям, правам, интеграциям, тестированию и сопровождению.
- agents/openai.yaml — имя, описание и настройки вызова skill.
- scripts/validate-skill.ps1 — проверка целостности пакета и публичной папки без изменения файлов.
- scripts/check-bsl-hook.ps1 и hooks/codex-post-tool-use.example.json — необязательный Codex hook для кандидатов на ревью в изменённых строках BSL.
- XML-каталоги-шаблоны для внешних отчётов и обработок.

Локальные пользовательские настройки не входят в репозиторий. Созданный при использовании файл user-context/user-preferences.yaml игнорируется Git.

## Проверка пакета

Из корня каталога skill запустите `pwsh -NoProfile -File ./scripts/validate-skill.ps1`.
Для папки, подготовленной к публичной загрузке, добавьте `-Public`; проверка обнаружит включённый профиль пользователя, отсутствие его правила в `.gitignore` или каталог `.git`.

## Необязательный BSL hook Codex

Hook выключен по умолчанию. Чтобы включить его, оставьте `scripts/check-bsl-hook.ps1` в папке установленного skill или скопируйте в доступное место, добавьте конфигурацию из `hooks/codex-post-tool-use.example.json` в `~/.codex/hooks.json` или доверенный проектный `.codex/hooks.json` и замените `<ABSOLUTE_PATH_TO_1C_UNIVERSAL_DEV>` на фактический путь к скрипту. Для ограничения одним проектом предпочтите проектную конфигурацию; глобальная сработает во всех проектах. Существующие hooks сохраняйте и объединяйте вручную, не перезаписывайте конфигурацию целиком. После добавления просмотрите и подтвердите hook в Codex.

Hook работает после `apply_patch` и передаёт модели список изменённых `.bsl`-файлов. Главный сигнал — подтверждённое нарушение явного правила проекта или пользователя, с указанием источника правила и места изменения. Если изменённые строки содержат признаки запроса, дополнительно применяется `references/query-review-1c.md`; без запроса эта часть проверки пропускается. Общие BSL-антипаттерны сами по себе замечаниями не считаются; при отсутствии подтверждённого нарушения hook ничего не сообщает.

Hook не блокирует и не изменяет файлы, не отправляет данные по сети и не пишет локальный журнал. Это ничего не говорит о возможном учёте со стороны Codex или корпоративной платформы. Hook — подсказка для проверки правил, а не замена ревью, проверке платформой или АПК. Он видит только поддерживаемые изменения через `apply_patch`. Требуется PowerShell; для Windows пример использует `powershell.exe`, для macOS/Linux — `pwsh`.

Перед выбором режима skill сначала определяет, требуется ли только анализ, исправление данных без изменения конфигурации или изменение поведения конфигурации. Если направление неясно, он задаёт один вопрос и ждёт ответа. Перед конфигурационной доработкой skill читает применимые правила проекта и не предлагает реализацию, если не может соблюсти их полностью.

Режимы `данные`, `ревью` и `БСП` можно указать явно в запросе к skill; остальные режимы выбираются по общим правилам из `SKILL.md`.

## Установка

Установите папку этого репозитория в каталог skills вашей версии Codex либо добавьте её в проект в .agents/skills/1c-universal-dev/. Актуальные варианты установки описаны в [документации Codex Skills](https://developers.openai.com/codex/skills).
