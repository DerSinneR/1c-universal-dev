# Режим `архитектура`: проектирование 1С-решений

Используй для проектирования подсистем, метаданных, моделей данных, документов, регистров, справочников, внешних обработок, расширений и крупных доработок типовых конфигураций.

## Что определить в начале

- Бизнес-цель и граница задачи: учет, интерфейс, интеграция, отчетность, контроль, сервисная операция.
- Версия платформы, режим совместимости, тип приложения и форма: обычная или управляемая.
- Типовая конфигурация на поддержке, нетиповая конфигурация, расширение или внешняя обработка.
- Какие данные являются мастер-данными, какие являются событиями, какие являются расчетными итогами.
- Требуется ли обновляемость типовой конфигурации и переносимость между версиями.
- Объем данных, количество пользователей и требования к производительности.

## Выбор объектов метаданных

- Справочник выбирай для устойчивых сущностей: контрагенты, номенклатура, договоры, настройки, классификаторы.
- Документ выбирай для фактов хозяйственной операции, которые имеют дату, автора, проведение, движения и отмену.
- Регистр сведений выбирай для состояний, настроек, соответствий, периодических значений и независимых фактов без оборотов.
- Регистр накопления выбирай для остатков и оборотов по измерениям, когда важны движения и период.
- Регистр бухгалтерии и расчета выбирай только при реальной учетной модели, не как универсальную таблицу.
- Перечисление используй для закрытого набора значений, который меняется редко и входит в логику конфигурации.
- Константу используй только для одного значения на базу; не превращай константы в склад настроек подсистемы.
- Для фактических имён объектов используй общее правило из `SKILL.md`; имена новых объектов обозначай как проектные предложения.

## Слои решения

- Для существующих форм применяй ограничение проекта из `references/form-review-1c.md`.
- Бизнес-правила — в модуле объекта, менеджера или серверном общем модуле по смыслу ответственности.
- Доступ к данным и тяжелые запросы — на сервере.
- Интеграционный контракт — отдельно от UI и внутренних форм.
- Технические операции — отдельными серверными процедурами с журналированием, отбором и повторным запуском.

## Типовые конфигурации и расширения

- Для типовой конфигурации сначала ищи настройку, БСП-механизм, переопределяемый модуль, подписку или расширение.
- Изменение основной конфигурации рассматривай как последний вариант, если обновляемость не является приоритетом или другие варианты доказанно не подходят.
- Не копируй крупные фрагменты типового кода в расширение без причины: это повышает риск конфликтов при обновлении.
- Для каждого расширения фиксируй зависимость от версии поставщика и сценарий проверки после обновления.
- Для выбора и подключения подсистемы БСП используй маршрут `references/bsp-review-1c.md`.

## Проектирование движения данных

- Для документа сначала определи: что является фактом, какие регистры он меняет, как отменяется проведение, как работает перепроведение.
- Не рассчитывай итоговое состояние только в табличной части документа, если оно нужно для отчетов, отборов и интеграций.
- Для регистров определяй измерения по будущим отборам и отчетам, а ресурсы — по агрегируемым величинам.
- Не добавляй измерение в регистр только «на всякий случай»: оно влияет на объем данных, индексы, отчеты и производительность.

## Версии 8.1, 8.3 и 8.5

- Для 8.1 и режима совместимости 8.1 проектируй максимально консервативно: обычные формы, толстый клиент, минимальная зависимость от современных механизмов.
- Для 8.3 учитывай точный релиз, особенно если решение зависит от расширений, EDT, АПК, web-клиента или БСП.
- Для 8.5 проверяй релиз и режим совместимости, особенно по формам интерфейса, EDT и XML-выгрузке.

## Формат архитектурной рекомендации

1. Цель и границы решения.
2. Предлагаемая модель метаданных.
3. Где находится логика: форма, объект, менеджер, общий модуль, регистр, интеграционный слой.
4. Как решение обновляется и сопровождается.
5. Риски: права, производительность, транзакции, блокировки, расширения, совместимость версий.
6. Минимальный план реализации и проверки.

Для архитектурных утверждений используй тематический указатель в `references/source-policy-1c.md` и проверяй материалы, применимые к целевой версии.
