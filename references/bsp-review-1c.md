# Режим `БСП`: выбор и подключение стандартных подсистем

Используй вместе с основным режимом задачи, если решение зависит от механизма или API Библиотеки стандартных подсистем. Не читай этот файл для задач, не связанных с БСП.

## Рабочий порядок

1. Установи фактическую версию БСП и конфигурации по исходникам проекта, сведениям пользователя или официальной документации. Не считай версию 3.2.1 или другую версию установленной по умолчанию.
2. Найди подходящую подсистему и способ её подключения для этой версии. Учитывай требования к метаданным, настройкам, параметрам и инициализации только после проверки по исходникам или официальной документации.
3. Перед выдачей кода примени правила `Проверка точных имён и API` из `SKILL.md`: подтверди существование метода, сигнатуру, экспортность и клиентский/серверный контекст.
4. Сравни штатный механизм БСП с собственной реализацией по соответствию задаче, зависимости от обновления и объёму изменений.
5. Укажи, какие зависимости и настройки нужны, где разместить вызов, какие сценарии проверить и что может измениться при обновлении БСП.

## Если исходников нужной версии нет

- Не подставляй API из примера другой версии и не угадывай подготовительные действия.
- Попроси выгрузку соответствующего модуля/подсистемы или точную ссылку на документацию нужной версии, если без них нельзя подтвердить готовый вызов.
- До проверки можно дать концептуальное направление, но обозначь точные имена и вызовы как неподтверждённые.

Не включай в skill статический полный справочник API БСП: для рабочей задачи используй проектную версию, чтобы не закреплять устаревшие сигнатуры и неподтверждённые зависимости.
