# Режим `расширение`: анализ расширений 1С

Используй для `.cfe`, заимствованных объектов, собственных объектов расширения, переопределений, подписок, ролей и оценки обновляемости.

## Что определить в начале

- Цель изменения: исправление, интеграция, печатная форма, интерфейс, права, бизнес-правило.
- Конфигурация и версия поставщика.
- Версия платформы и режим совместимости.
- Какие объекты заимствованы, какие добавлены в расширении.
- Это изменение должно переживать обновления типовой конфигурации или является временным обходом.

## Чек-лист анализа

### Выбор способа расширения

- Предпочитай безопасные точки расширения: подписки, переопределяемые модули, дополнительные реквизиты/сведения, команды, печатные формы, БСП-механизмы, если они есть.
- Для существующих форм соблюдай ограничение проекта: не меняй их XML/метаданные и не заимствуй форму для структурной доработки; разрешён только код модуля формы в расширении. Если этого недостаточно, явно обозначь ограничение и ищи вариант без изменения формы.
- Не меняй типовое поведение через копирование больших фрагментов типового кода без причины.

### Обновляемость

- Оцени, насколько изменение зависит от внутренней реализации поставщика.
- Проверь риск конфликта при обновлении: заимствованные методы, формы, реквизиты, роли, команды.
- Для каждого заимствования требуй причину и сценарий проверки после обновления.

### Код расширения

- Проверяй, не обращается ли расширение к приватным деталям типовой конфигурации, которые могут измениться.
- Проверяй клиент/серверный контекст так же строго, как в обычном BSL-коде.
- Для подписок проверяй порядок выполнения, повторный вход, отказ, транзакции и влияние на проведение.

### Права

- Новые объекты расширения должны иметь понятную модель доступа.
- Не использовать привилегированный режим для обхода ролей без архитектурного обоснования.
- Проверить, как изменение работает для пользователя без полных прав.

### Данные

- Если расширение добавляет регистры, справочники или реквизиты, проверь миграцию данных, заполнение, очистку и отчётность.
- Для изменений в проведении оцени влияние на движения и закрытие периода.

## Формат вывода

- Можно ли делать через расширение: да, нет, условно.
- Какой способ расширения предпочтителен.
- Какие объекты заимствовать, а какие не заимствовать.
- Риски обновления и как их проверить.
- Минимальный набор тестов: обновление типовой, пользовательские права, проведение/отмена, web-клиент при необходимости.
