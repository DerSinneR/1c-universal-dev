# Локальный профиль пользователя 1С

Используй этот reference в начале 1С-задачи, когда нужно учесть сохраненные предпочтения пользователя и не задавать повторные вопросы про инструменты, формат результата и рабочий процесс.

## Файл профиля

Основной файл профиля:

```text
user-context/user-preferences.yaml
```

Файл хранит локальные ответы пользователя. Не считай его официальной документацией 1С и не используй для подтверждения поведения платформы. Это только профиль предпочтений пользователя и проекта.

## EDT

Ключевой параметр:

```yaml
preferences:
  edt_usage:
    value: "unknown"
```

Допустимые значения:

- `yes` — пользователь работает с 1C:EDT; EDT можно учитывать как основной инструмент в workflow.
- `no` — пользователь не работает с 1C:EDT; не предлагай EDT как основной сценарий.
- `sometimes` — EDT иногда применяется; сначала давай вариант без EDT, EDT указывай как дополнительный вариант.
- `unknown` — ответ еще не зафиксирован; в начале 1С-задачи нужно спросить пользователя.

## Как спрашивать

Если `edt_usage.value` отсутствует или равно `unknown`, задай один короткий вопрос:

```text
Вы работаете с 1C:EDT в этом проекте? Ответьте: да, нет или иногда.
```

После ответа пользователя зафиксируй значение:

- `да` → `yes`;
- `нет` → `no`;
- `иногда`, `не всегда`, `зависит от задачи` → `sometimes`.

Если пользователь не ответил, не выдумывай значение. Продолжай только с явно обозначенным предположением, если задача не зависит от EDT; профиль при этом не обновляй.

## Как обновлять профиль

Обновляй `user-context/user-preferences.yaml`, когда пользователь явно ответил на вопрос или явно изменил настройку. Дополнительное подтверждение не требуется, потому что пользователь заранее попросил фиксировать такие ответы в локальном профиле.

При обновлении:

- измени `updated_at` на текущую дату;
- поставь `source: "user_answer"`;
- поставь `fixed_until_user_changes: true`;
- обнови `note` коротким объяснением.
- Сохраняй остальные ключи и предпочтения; не заменяй весь профиль примером, содержащим только EDT.

Пример для пользователя, который не работает с EDT:

```yaml
schema_version: 1
updated_at: "2026-10-05"
preferences:
  edt_usage:
    value: "no"
    source: "user_answer"
    fixed_until_user_changes: true
    note: "Пользователь не работает с EDT; не предлагать EDT как основной сценарий."
```

## Как использовать профиль в ответах

Если `edt_usage.value: "yes"`:

- можно предлагать EDT как основной вариант;
- для XML/EDT-проектов учитывай EDT в проверках и структуре результата;
- при необходимости добавляй вариант через Конфигуратор как альтернативу.

Если `edt_usage.value: "no"`:

- не предлагай EDT как основной сценарий;
- основной путь: Конфигуратор, XML-каталог, ручная загрузка или другой разрешенный пользователем инструмент;
- если EDT важно упомянуть, пометь его только как альтернативу и объясни, что основной путь выбран без EDT по сохраненному профилю.

Если `edt_usage.value: "sometimes"`:

- сначала предлагай путь без EDT;
- EDT упоминай как дополнительный вариант;
- для конкретной задачи можно уточнить, если выбор инструмента меняет результат.

Если `edt_usage.value: "unknown"`:

- задай вопрос в начале 1С-задачи;
- не делай вид, что пользователь работает или не работает с EDT;
- не записывай профиль без ответа пользователя.

## Не перезаписывай без явного сигнала

Не меняй сохраненное значение только потому, что в задаче встретились слова `EDT`, `XML`, `Конфигуратор` или `.epf/.erf`. Обновляй профиль только при прямом ответе или явной фразе пользователя, например:

- `теперь работаем через EDT`;
- `EDT не используем`;
- `для этого проекта EDT иногда используем`;
- `запомни, что EDT нет`.

## Персональный формат выдачи BSL

Если `preferences.bsl_output_format.value` равно `compact_user_style`, при выдаче и переписывании BSL-кода применяй формат, согласованный с пользователем:

- Вызовы методов и условия преимущественно размещай в одну строку.
- Действительно длинные выражения переноси по смыслу, без излишнего дробления аргументов. Не устанавливай искусственный лимит длины строки.
- Накопление `ТекстОшибки` оформляй отдельными строками: присваивание, `+ СтрШаблон(...)`, `+ Символы.ПС`. Длинный `СтрШаблон` при необходимости переноси.
- Перед основными этапами многошагового алгоритма используй краткие нумерованные комментарии; не комментируй каждую очевидную строку.
- Пустыми строками разделяй логические блоки, отступами показывай вложенность. В существующем коде сохраняй принятую схему отступов.
- При переписывании предоставляй цельный фрагмент для замены, а после него — короткое пояснение и обязательные сопутствующие изменения.
- Сохраняй имена переменных и стиль исходного кода, если изменение не требуется для исправления ошибки или прямо не запрошено пользователем.

Пример оформления сообщения:

```bsl
ТекстОшибки = ТекстОшибки
    + СтрШаблон("Заказ %1: ошибка проведения: %2", Выборка.ВнешнийИдентификатор, ОписаниеОшибки())
    + Символы.ПС;
Продолжить;
```

Это персональное предпочтение, а не обязательный стандарт фирмы «1С». Оно не меняет требования к корректности, правам, транзакциям и обработке ошибок. Явное указание пользователя в текущей задаче имеет приоритет. Если настройка отсутствует, не приписывай пользователю это предпочтение и не задавай отдельный вопрос без необходимости.

Обновляй это предпочтение только по явной просьбе пользователя, сохраняй `source: "user_answer"`, `fixed_until_user_changes: true` и дату обновления профиля.

## Самоаудит

Если сохраненный профиль повлиял на выбранный workflow, в блоке `Самоаудит выполнения` коротко укажи это. Пример:

```text
Профиль пользователя: EDT не используется, поэтому основной сценарий сформирован через XML-каталог и ручную загрузку в Конфигуратор.
```
